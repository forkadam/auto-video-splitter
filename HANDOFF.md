## What's built

### vsplit (CLI, v1.0)

Python CLI that scans a folder of personal video clips, detects scene boundaries with PySceneDetect, gates on a human review step, and losslessly splits each file via FFmpeg. Per-file workspaces under `.vsplit/`, manifest-driven, resumable, failure-isolated.

7 stages: `probe → detect → preview → review → plan → split → verify`.
7 CLI commands: `scan, run, status, approve, reset, clean, one`.

### vsplit dashboard (v0.2)

Localhost FastAPI server + React/Vite/Tailwind/shadcn frontend. Launched via `vsplit dashboard`. Localhost-only (127.0.0.1), no auth, single-user.

Features:
- Workspace list (hybrid collapsible rows) with per-stage status pips.
- Per-row actions: Run / Reset / Clean / Approve, plus a button to open the existing preview HTML in a new tab.
- Bulk selection + filter bar (status / stage / slug glob — same grammar as the CLI).
- Failed-stage log drawer (click a red pip).
- Config drawer: structured form for common fields + collapsible raw-YAML pane, validated server-side via Pydantic.
- Live status updates via Server-Sent Events; both in-process action callbacks and a manifest-mtime watcher thread feed the broker, so external `uv run vsplit ...` invocations are reflected too.

## How to use it

```powershell
# Toolchain
uv venv
uv pip install -e ".[dev]"

# CLI
uv run vsplit --help
uv run vsplit scan ~/some-folder
uv run vsplit run
uv run vsplit run  # finishes plan/split/verify after editing cuts.json
ls .vsplit/workspaces/*/output/

# Single-file shortcut
uv run vsplit one ~/Birthday.mov --auto-approve

# Dashboard
uv run vsplit -w ~/some-folder dashboard
# Opens http://127.0.0.1:8765 in your browser. Ctrl-C to quit.

# Tests
uv run pytest -q                          # 136 passed
uv run python tests/fixtures/make_fixtures.py  # one-time fixture generation
```

- **Dashboard:** `cuts.json` inline editor is out of scope for v1 (use a text editor); thumbnails in expanded workspace rows are placeholder gray boxes (real per-scene thumbs are a v1.1 item); no Playwright e2e tests on the React frontend.

- **Test coverage gaps in dashboard:** no tests for `--dry-run` equivalents, batch run-with-options, or front-end logic.

These are tracked, not blockers.

## Bug fixes that landed in v0.2.0 (worth remembering)

Dashboard implementation surfaced these real bugs:

- **EventBroker async-gen → class-based iterator (Python 3.13):** PEP 479 + `asyncio.wait_for(anext(gen), timeout=...)` would close the generator permanently on timeout. Rewrote `subscribe()` as a lazy-registering class iterator.
- **SSE testing via `TestClient.stream()` blocks the event loop** on infinite generators. Tests use real uvicorn in a thread + httpx streaming.
- **`run_finished` event must reflect actual outcome** — initial implementation hardcoded `ok: True`; fix reloads manifest and computes from stage statuses.
- **Slug validation gap on detail/log endpoints:** path-traversal-style slugs reached `workspace_dir()` before any check. Added `_require_slug` mirror of the actions-endpoint pattern.
- **`vsplit dashboard` requires `httpx` in dev deps** (for FastAPI's TestClient). Discovered during T6.
- **Tailwind v4 not v3:** No `tailwind.config.ts`; uses `@tailwindcss/vite` plugin + CSS-based config. Implementer adapted.
- **shadcn `toast` deprecated → `sonner` substituted** (and patched to remove its `next-themes` dependency for Vite-only project).

Highest-value follow-ups in priority order:

4. **Address deferred validators/coverage** in `project_deferred_tech_debt.md`.
5. **`ReviewStage.recover()` override** to preserve `cuts.json` if a crash hits mid-review-edit.
6. **Performance:** batch `preview` thumbnails via ffmpeg select filter (one process per scene instead of N).
7. **`.gitattributes`** to lock LF endings for repo files.
