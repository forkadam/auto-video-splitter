## What was built

vsplit v1 — a Python CLI that scans a folder of personal video clips, detects scene boundaries with PySceneDetect, gates on a human review step, and losslessly splits each file via FFmpeg. Per-file workspaces under `.vsplit/`, manifest-driven, resumable, failure-isolated. Designed for vacation/event footage (50–200 short clips per trip on Windows). Default behavior is curation-friendly: keep few, drop many.

## Known deferred items

See `~/.claude/projects/D--workspace-auto-video-spliter/memory/project_deferred_tech_debt.md` for the full list. These were tracked during implementation but deliberately not fixed in v1. Highlights:

- **Hygiene:** version-string dup between `pyproject.toml` and `vsplit/__init__.py`; no `.gitattributes` for CRLF/LF on Windows; `[tool.ruff.lint]` config is sparse.
- **Subprocess cancellation:** spec §5.6 promises clean shutdown on Ctrl-C with terminate/kill grace. Only `split` polls `cancel_event` per segment; other stages (probe, detect, preview, plan, verify) run full subprocesses without listening for cancellation.
- **No subprocess timeouts:** hung ffmpeg/ffprobe blocks the worker indefinitely.
- **Review-stage recover:** default `Stage.recover()` deletes `decisions/`. User edits to `cuts.json` would be lost if the orchestrator's `_recover_running` ever fires on review (only happens when review itself crashes mid-write). Design-correct per spec; documenting for future devs.
- **Test coverage gaps:** scan command lacks tests for `--dry-run`, `--recursive`, `--auto-relocate`, rename-detection, replaced-file warning; review-gate lacks test for `auto_apply_template=False` with template present; preview lacks `.mkv` coverage.

These are tracked, not blockers.

## Bug fixes that landed in v1 (worth remembering)

Several real correctness bugs surfaced and got fixed during implementation. They're now in the code, but the *root causes* are worth knowing if similar work happens later:

- **Slug edge cases (`fix(core): handle empty/control-char/trailing-hyphen/overlong slug edge cases`):** `slugify('<>:.mp4')` returned `""`; control chars passed through; truncation could leave trailing hyphen; `resolve_collision` could exceed MAX_LEN. All fixed.
- **Path-length estimate (`fix(core): widen project_path_length_estimate to include output filename`):** The plan picked `preview/images/scene-XXX-XX.jpg` as the deepest tail, but `output/<slug>-highlight-NN-label.mp4` is significantly longer.
- **Config global layer (`fix(core): add global config layer per spec §3.4 ...`):** Plan's snippet omitted the `~/.config/vsplit/config.yaml` layer.
- **Preview stage end-of-file seek:** ffmpeg fails seeking to exactly `end_time`; clamped to `end_time - ε`.
- **Plan stage CSV parsing:** Windows ffprobe emits SEI message annotations alongside `pts_time`; CSV parser now splits on `,` and takes the first field.
- **FileHandler leak in pipeline logger:** Removed handlers were never closed; would block log file re-creation on Windows.
- **Schema validators in final fix:** Manifest stage-key validator, Config.concurrency validator, CutsJson timestamp regex + Scene.id uniqueness.

## Future work (post-v1)
